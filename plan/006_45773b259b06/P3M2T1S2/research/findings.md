# Research findings — P3.M2.T1.S2 (atomic persistence, durability, monotonicity, honest failure)

## 1. Binding requirement text (READ-ONLY)

`spec/state-and-persistence.md` §Local input recovery, "Recovery point" bullet (:141):

> A completed local save must survive restart within the OS and storage system's durability guarantees. Replace it atomically: an interrupted write leaves the previous or new complete value, never a torn one. Older writes and incidental empty buffers (initialization, view change, send cleanup) must not overwrite newer user edits. On write failure keep the last durable value and the live edit; never claim the edit was saved. Recovery guarantees the latest completed save, not keystrokes the editor never received or a write still in flight.

Sibling bullets that bound scope: "Drafts are not answers or messages" (no advance/commit/queue/submit/send/resend/model call — S3 audits), acceptance case 3 (fail a write / delay an older write past a newer edit / cross-branch switch), case 2's kill-during-typing (progression half). Retirement, restore, and blank rejection are S3/P3.M3/P3.M4 — NOT this item.

## 4. Design decisions locked for this PRP

1. **New module `src/input-durability.ts`**, class `DurableInputStore`, SYNC fs only. Sync is the honest choice for a crash-recovery store: a flush callback returns only when the save is fsynced+renamed (durable), so there is never a "promise pending" window between bookkeeping and disk; tiny files + ≥250ms pacing make sync cost irrelevant. (persistence.ts flush precedent.)
2. **Write protocol** (all inside try/catch; never throws to the sink): normalize key (`questionId ?? "-"`, `seq <= 0` → never wins) → monotonic guard (`record.seq < durable.seq` → `ignored-stale`) → incidental-empty guard (`text === ""` with NO durable record → `skipped-empty`) → `mkdirSync(recursive)` → tmp file `<name>.<pid>.<n>.tmp` in the SAME dir → `openSync("w")`/`writeSync`/`fsyncSync`/`closeSync` → `renameSync(tmp, file)` → best-effort dir fsync (POSIX; Windows `openSync(dir)` throws — try/catch ignored) → update in-memory index → `"written"`. On any fault: best-effort `rmSync(tmp)`, durable file untouched, return `"failed"`.
3. **Filename**: `input-<slug>-<sha1hex>.json` — slug = sanitized(`field` + `--` + `questionId`) ≤ 48 chars (cosmetic, debuggable), full sha1 of the canonical key JSON (uniqueness; question ids are model-authored arbitrary strings — hashing defeats path traversal/slashes). Index keyed by the PARSED payload key, not the filename (collision-proof).
4. **Payload** `{v: 1, key: {session, branchId, questionId, field}, text, seq, savedAt}` — self-describing; P3.M3/S3 can inspect files by hand.
5. **Restart seeding (the monotonicity hole S2 must close)**: S1's in-memory per-key counters reset each process. Without seeding, post-restart edits mint seq 1 and the monotonic guard would reject them against the durable file's higher seq — or (worse, if the guard compared text recency) clobber. Resolution per architecture note: `DurableInputStore` constructor scans the dir and indexes every valid file; `lastSeq(key)` answers seeds; S2 adds an OPTIONAL additive `seedSeq?: (key) => number` option to `InputCaptureStore` consulted at the FIRST seq mint per key (lazy — no fs on construction of the capture store). index.ts wires `seedSeq: (k) => durable.lastSeq(k)`.
6. **Read API for P3.M3**: `latest(key): {text, seq} | undefined` from the in-memory index (loaded at construction, updated on write). `undefined` = never captured; `{text: "", seq}` = deliberate delete-to-empty (spec :142 "an intentional deletion to empty is an edit") — P3.M3's seeding rules depend on this distinction. Recovery truth is the DURABLE store only — S1's in-memory `latest()` is the live edit, never a "saved" claim.
7. **Honest failure = no surface**: the store exports only data/write APIs (`write`/`latest`/`lastSeq`), an internal outcome enum for tests, and NO events/Emitter/render hooks anywhere. "Never claim the edit was saved" is satisfied structurally (nothing to render) — plus a structural test + grep guard.
8. **Shutdown**: `pi.on("session_shutdown", () => capture.forceFlush())` — accelerator flush through the sync sink; NEVER dispose (factory outlives session replacement; a disposed store would never re-arm). In-flight-at-kill = unsaved, and nothing promised it.
9. **No config keys** (architecture note defers overrides; config-surface.test.ts would otherwise need reshaping). Constructor options (dir/fs/now) are test seams, not user config.
